# 对象指标首次发布全量功能测试设计

> 状态：首次发布验收基线。本文中的 P0、P1 均属于发布前必跑项；P2 仅允许在明确记录风险并获得发布负责人接受后延期。

## 1. 目标

本套测试验证用户能否只通过页面完成对象指标的完整业务闭环，而不是只验证控件渲染或接口返回：

1. 准备可重复的对象、关系和实例数据。
2. 在页面创建单实例/实例集的原子、衍生、复合指标。
3. 保存草稿并重新进入，确认配置没有丢失或被静默改写。
4. 在发布前试算真实数据，并核对明确的业务结果。
5. 执行配置校验，确认问题定位和处理建议准确。
6. 发布指标，确认详情、版本、依赖和返回契约正确。
7. 将单实例指标绑定为逻辑属性，在对象类逻辑属性区域再次试算。
8. 验证无数据、空值、除零、时间边界、关系去重和历史版本等高风险口径。

通过标准不是“请求成功”，而是页面展示的配置、提交的定义、实际计算结果和发布后的详情四者一致。

## 2. 名词与范围

- **单实例**：输入一个对象主键，每个对象实例最多返回一个指标值。
- **实例集**：在一个对象集合上计数、聚合、分组或按时间分桶。
- **原子指标**：只定义基础事实或基础聚合，不附加状态、渠道、时间窗口等业务限定。
- **衍生指标**：继承一个已发布原子指标，只增加业务条件、关联条件、时间范围或结果粒度。
- **复合指标**：组合至少两个已发布指标，并明确对象、时间、粒度、空值和除零规则。
- **逻辑视图**：本计划指对象类详情中的逻辑属性区域及逻辑属性试算。数据目录中的 `logicview` 是另一种资源类型，不与对象指标直接等同；若产品要求指标进入数据目录逻辑视图，应另建跨模块套件。
- **页面 E2E**：指标的选择、配置、试算、校验、保存、发布和逻辑属性验证必须通过浏览器页面操作。

## 3. 自动化边界

### 3.1 必须从页面完成

- 创建六类指标组合：单实例/实例集 × 原子/衍生/复合。
- 填写所有业务字段和高级字段。
- 保存草稿、刷新、重新进入编辑页。
- 检查配置/语义校验、查看返回契约。
- 发布前试算、发布、发布后试算。
- 预配置逻辑属性、发布后补绑逻辑属性、逻辑属性试算。
- 查看指标详情、依赖版本、血缘和对象类逻辑属性。

### 3.2 接口只用于

- 创建独立测试知识网络并导入确定性模型和实例数据。
- 查询数据库/API 作为页面结果的交叉证据。
- 清理草稿和可安全删除的测试资源。
- 失败时保存请求/响应，不能用接口替代页面创建指标。

### 3.3 隔离策略

- 默认使用独立网络 `metric_e2e_<run_id>`，不在人工使用的 `ecommerce_ops_bkn` 中发布测试指标。
- 所有指标名称和逻辑属性名使用 `E2E_<run_id>_` 前缀。
- 已发布版本不可删除时，整套网络作为一次性测试资源统一回收。
- Playwright 串行运行；同一套件内部通过已发布基线指标构建后续依赖。

## 4. 确定性业务模型与数据

### 4.1 对象类

#### 销售订单 `order`

| 属性                 | 类型          | 说明                                   |
| -------------------- | ------------- | -------------------------------------- |
| `order_id`           | string        | 主键                                   |
| `payment_amount`     | decimal       | 实付金额，CNY                          |
| `shipping_fee`       | decimal       | 运费，CNY                              |
| `status`             | string        | `completed/refunded/cancelled/pending` |
| `channel_id`         | string/null   | 渠道外键                               |
| `payment_time`       | datetime/null | 支付时间                               |
| `complete_time`      | datetime/null | 完成时间                               |
| `cancel_time`        | datetime/null | 取消时间                               |
| `legacy_amount_text` | string        | 用于测试显式文本转数值                 |

#### 销售渠道 `channel`

| 属性              | 类型    | 说明           |
| ----------------- | ------- | -------------- |
| `channel_id`      | string  | 主键           |
| `channel_type`    | string  | `web/offline`  |
| `enabled`         | boolean | 是否启用       |
| `commission_rate` | decimal | 佣金率，无量纲 |

#### 订单明细 `order_item`

| 属性          | 类型    | 说明          |
| ------------- | ------- | ------------- |
| `item_id`     | string  | 主键          |
| `order_id`    | string  | 订单外键      |
| `item_amount` | decimal | 明细金额，CNY |
| `category`    | string  | 商品分类      |

### 4.2 关系类

| 关系                               | 基数   | 用途                               |
| ---------------------------------- | ------ | ---------------------------------- |
| `order_from_channel`：订单 → 渠道  | 多对一 | 衍生关联筛选、单实例复合跨对象对齐 |
| `order_contains_item`：订单 → 明细 | 一对多 | 验证“任一满足”和当前订单身份去重   |

## 11. 每条用例统一执行模板

每条自动化用例必须按以下顺序留下证据：

1. **前置检查**：确认知识网络、对象类、关系类、属性和实例数据存在。
2. **页面进入**：从对象指标列表选择对象类和指标类型进入创建页，不能直接拼隐藏参数绕过入口校验。
3. **页面配置**：通过可见标签、角色和控件完成配置。
4. **草稿恢复**：保存后刷新或重新进入，逐项断言关键配置。
5. **发布前试算**：输入实例/时间/分析维度，断言状态、值、单位、维度和时间桶。
6. **配置校验**：断言通过；负向用例断言精确问题和建议。
7. **返回契约**：断言输出形态、值类型、单位、固定维度和时间键。
8. **发布**：断言版本和状态；单实例按用例验证逻辑属性。
9. **发布后试算**：使用同一运行参数复算，与草稿结果比较。
10. **详情核对**：核对业务定义、技术表达式、依赖版本、时间口径、无数据策略和血缘。

## 14. 完成判定

一类场景只有同时满足以下条件才能标记通过：

- 页面可以完成配置且草稿恢复正确。
- 页面试算得到可核对的真实值，不只是 `200 OK`。
- 校验和返回契约与配置一致。
- 发布后再次试算结果一致。
- 详情页显示精确版本、单位、时间、粒度和依赖。
- 单实例逻辑属性与指标结果一致；实例集不允许绑定。
- 无浏览器错误、无未处理请求错误、无加载中错误态闪烁。

任何一项失败都记录为产品问题，不允许用接口直写数据或跳过页面步骤让用例“变绿”。

## 15. 首次发布评审结论

原有 AI/AS/DI/DS/CI/CS、逻辑属性、试算、生命周期和校验共 84 条场景，能够覆盖核心闭环，但不能单独作为首次发布的全量验收。发布前还必须满足以下门槛：

1. **必须有可执行用例**：当前 `tests/e2e/specs/knowledge-network` 下只有设计文档和一次人工执行报告，没有对象指标 Playwright 规格文件；文档中的场景不能计为“已测试”。
2. **所有页面可选项至少有一个正向用例**：聚合、运算符、函数、条件操作符、时间模式、结果策略和对齐方式均不能只测代表值。
3. **每条规则至少有一个反向用例**：不能只验证前端禁用，还要验证绕过页面提交时后端仍拒绝非法定义。
4. **结果必须可计算**：每条正向用例都要给出确定输入、精确期望值、状态、单位、维度和时间桶，不能以“记录实际行为”为断言。
5. **页面与接口分层**：用户可配置能力必须走页面 E2E；页面隐藏但后端公开的 V1 契约走 API 集成测试，并验证页面不会误展示或误提交。
6. **历史缺陷必须成为回归用例**：旧版已发布定义的值类型兼容、衍生/复合草稿试算、存在错误时校验总状态不得为成功，均纳入 P0。

### 15.1 已确认的契约

- 固定时间范围按当前执行引擎使用闭区间 `[start_at, end_at]`；页面选择整日结束日期时必须提交该日 `23:59:59.999`，不能提交下一日 `00:00:00.000`。
- `count` 和 `count_distinct` 都忽略 `null`；`count_rows` 统计行数。
- 页面当前只允许新建“存在任一满足条件的关联实例”（`exists`）。`not_exists/all/all_nonempty/count_compare` 只用于兼容历史定义和后端契约，不应在新建页暴露。
- 页面统一使用 `UTC`，不再允许用户重复配置时区；后端仍需拒绝非法 IANA 时区。
- 页面当前固定提交 `partial_data_policy=reject`；`allow_with_warning` 作为后端契约单独验证，前端不得声称可配置该策略。

## 17. 覆盖追踪与执行准入

### 17.1 测试层级分工

| 能力                                   | 页面 E2E            | API 集成     | 单元/组件  |
| -------------------------------------- | ------------------- | ------------ | ---------- |
| 用户可见的创建、恢复、试算、校验、发布 | 必须                | 关键契约     | 交互边界   |
| 所有下拉选项和条件运算符               | 每项至少一次        | 非法组合     | 纯映射穷举 |
| 页面隐藏的 V1 高级契约                 | 验证不暴露/只读兼容 | 必须         | 序列化映射 |
| 权限、分页、截断、并发、故障           | 用户表现            | 必须         | 状态机     |
| 计算正确性                             | 代表性业务链路      | 全枚举与边界 | 纯函数     |

### 17.2 用例状态字段

可执行规格和执行报告必须为每个 ID 记录：`implemented / passed / failed / blocked / not_run`、目标环境版本、提交 SHA、测试数据 run id、实际值、失败证据和缺陷编号。`blocked` 与 `not_run` 不计为通过。

### 17.3 首次发布准入标准

- P0 用例实现率和通过率均为 100%。
- P1 用例实现率和通过率均为 100%；确需延期必须逐条记录风险、替代验证和负责人，不允许整类跳过。
- 所有后端公开枚举至少有一条正向契约测试，所有页面可见枚举至少有一条页面正向用例。
- 高风险边界：时间、空值、除零、关系去重、单位、权限、分页截断、并发、版本固定均有真实结果证据。
- 无未关闭的 P0/P1 缺陷；不存在以“环境问题”为名长期跳过的主链路。
- fixture 创建和清理可重复运行；连续执行两次结果一致且不会污染人工网络。
