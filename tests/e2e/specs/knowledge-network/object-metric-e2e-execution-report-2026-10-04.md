## 2. 本轮发现的问题

### ISSUE-01：单实例数值属性在配置层与执行层的类型认知不一致

- 严重级别：P0
- 影响范围：单实例原子指标，以及依赖该原子指标的衍生、复合指标。
- 复现一：
  1. 新建单实例原子指标。
  2. 直接读取 `total_amount`。
  3. 页面自动识别为“小数 / 金额 / CNY”，配置检查通过。
  4. 使用订单 `10357` 试算。
- 实际结果：返回 `指标请求参数无效：result is not numeric`。
- 复现二：已发布指标“订单支付额@v5”使用 `(order.total_amount − order.discount_amount)`，详情显示 `decimal / amount / CNY`；订单 `10357` 试算时报“计算属性返回了文本值，不能直接进行四则运算”。
- 期望结果：属性元数据、编辑器校验和运行引擎应使用相同类型；若底层字段确为文本，编辑器必须要求显式 `to_number`，不能校验通过后才由运行时拒绝。

### ISSUE-02：发布前衍生、复合指标的真实数据试算不可用

- 严重级别：P0
- 影响范围：TR-01、DI、DS、CI、CS 的发布前试算闭环。
- 衍生复现：完整配置单实例衍生指标，语义校验通过，输入订单 `10357` 后试算。
- 复合复现：打开配置完整且页面显示“校验通过，可以发布”的单实例复合草稿 `test@v3`，输入订单 `10357` 后试算。
- 实际结果：两者均返回 `only a complete atomic object metric definition can be trialed before publication`。
- 期望结果：页面既然提供“试算当前配置”，后端应支持完整的原子、衍生、复合草稿；或者在后端能力未完成前隐藏入口并明确说明，而不是让用户填写参数后才失败。

### ISSUE-03：逻辑属性字段校验失败，但页面总状态仍显示通过

- 严重级别：P1
- 影响范围：单实例指标发布前配置逻辑属性。
- 复现步骤：
  1. 在单实例原子指标中开启“发布后作为逻辑属性使用”。
  2. 保持必填“属性名称”为空。
  3. 点击“检查配置”。
- 实际结果：字段下方出现“请输入逻辑属性名称”，但页面仍保留绿色提示“校验通过，可以发布”，发布按钮仍显示“发布指标并创建逻辑属性”。
- 期望结果：任一逻辑属性必填项失败时，总校验状态必须失败，且发布动作不可用或发布时能明确定位问题。

### 8.4 新发现问题（已修复）

#### ISSUE-04：`float64` 条件字段被识别为字符串

- 严重级别：P1
- 原始证据：`ObjectMetricConditionBuilder.test.tsx` 中 `normalizes float64 properties to the decimal condition type` 失败；期望 `decimal`，实际 `string`。
- 影响：当对象属性元数据使用 `float64` 时，条件编辑器会提供字符串操作符，而不是数值比较操作符，可能导致无法配置 `>`、`>=`、区间等合法数值条件。
- 对照证据：表达式注册和后端契约已经把浮点类型作为数值处理，问题仅出现在条件编辑器的类型归一化表。
- 修复：将 `float32`、`float64` 补充到条件类型的数值归一化表，统一映射为 `decimal`。
- 回归结果：同时覆盖 `float32` 和 `float64`，对象指标模块 17 个文件、164 条断言全部通过。
