# BKN Trace 0.1.4 统一高保真原型设计

## 目标

在现有 OpenBKN Studio 页面框架内，用同一份独立 HTML 验证两个相对独立的产品：

- 企业版“业务溯源分析”；
- 社区版“Trace 分析”。

两个页面共享顶部栏、左侧导航、字体、颜色、表格密度、详情面板和长文本交互，但不共享业务状态或解释逻辑。

## 原型入口

- 主入口：`public/bkn-trace-0.1.4-prototype.html`；
- 原业务溯源原型 URL 保留静态跳转，避免本地书签失效；
- 原型只用于交互验证，不复用 fixture 为生产代码。

## 导航

“可观测性”下展示：

- 业务溯源分析：保留现有黄色“企业版”标签；
- Trace 分析：不显示社区版或其他版本标签；
- 日志检索；
- 可观测性设置。

点击“业务溯源分析”和“Trace 分析”在同一页面壳内切换，面包屑、标题和正文同步更新。切换时关闭调用详情、技术详情、全文浮层和 Agent 抽屉。

## 业务溯源页面

保持已经确认的高保真结构：

- 业务会话列表、筛选和分页；
- Conversation 工作区和 Interaction 轮次列表；
- 当前轮次摘要；
- 时间链视图和知识网络视图；
- 右侧调用详情；
- Markdown 与 BKN Agent 分析。

不恢复并列 V2 产品语义，页面名称统一为“业务溯源分析”。

## Trace 分析页面

### Trace 列表

默认展示列表，而不是要求用户输入 Trace ID。保留最小筛选：时间、状态、服务/工具和精确 ID。表格展示开始时间、Trace/Request、根服务、状态、耗时、Span、Operation 和失败节点。

原型使用会话 `conv_73fc12a00ac46933c3d8015616a1b1b3` 两轮交互中已经确认的 9 次调用：`list_knowledge_networks` 1 次、`search_schema` 1 次、`query_object_instance` 1 次、`run_sql` 6 次。第一轮 8 次调用只展示已记录的工具、时间、耗时和输入输出事实，Request ID 与 Operation ID 明确显示“未记录”；第二轮 `run_sql` 展示已记录的真实 Request ID 和 Operation ID。所有调用均没有取得真实 Trace ID 或 Span，不生成模拟标识。

### Trace 详情

Trace 详情采用“单 Trace 技术执行工作台”：顶部展示 Trace 根输入和根输出原文、身份、时间、状态和采集完整性；中部展示确定性技术问题摘要；下方按真实时间和父子事实展示 Operation / Span；点击节点在右侧查看输入、输出、错误、ID、Attempt 和日志入口。

本原型的真实会话没有 Trace ID 和 Span，因此必须展示部分状态，并以 Interaction 输入、输出和已记录 Operation 组成时间序列。未观测区间只表示缺少调用事实，不解释为模型耗时。原型不展示 Token、模型耗时、模型成本或第三方 Agent 内部重试。

每次已记录调用占一行，选择列表行进入对应的单 Trace 工作台：

- 摘要：状态、耗时、Request、Span/Operation 数和部分原因；
- 执行链：按时间排列真实 Operation；
- 技术详情：接口、输入、输出或错误、时间和正式 ID；
- 关联日志入口。

不展示 Business Graph、Evidence Chain、Snapshot Preview、BKN 映射或业务建议。

## 全局长文本规则

所有常规页面表面上的长文本统一使用同一交互：

- 固定两行高度；
- 超出显示省略号；
- 鼠标悬浮显示带滚动的全文预览；
- 点击打开完整内容浮层；
- 全文浮层保留换行和 JSON / SQL 格式，支持复制和关闭；
- 切换菜单、列表项、会话、轮次、视图或详情节点时关闭旧全文。

适用范围包括：用户问题、Agent 输出、调用结果、查询条件、错误摘要、SQL、Agent 建议和 Trace Operation 输入输出。

悬浮预览只在文本实际被两行截断时启用，以元素的 `scrollHeight > clientHeight` 作为唯一判断。完整显示的短文本不出现预览，也不显示可点击手势。预览框采用约 320px 的紧凑宽度，跟随鼠标保持在右下方 14px；靠近视口右侧或底部时自动向左或向上避让。点击查看全文、复制和关闭行为保持不变。

完整内容浮层和右侧详情中的展开代码区不再做两行截断；它们是全文阅读态，而不是常规页面表面。

## 状态

原型至少覆盖：

- 业务溯源列表与会话详情；
- Trace 列表与详情；
- Operation 成功且有输入输出；
- Operation 缺少 Trace/Span 的部分状态；
- 两行截断、悬浮全文、点击全文和复制；
- 企业版标签只出现在业务溯源菜单。

## 非目标

- 不建设自由 Trace 拓扑图；
- 不补造 Trace ID 或 Span；
- 不增加社区版标签；
- 不重新设计业务溯源已经确认的主体布局；
- 不接真实 API 或执行真实 Agent 对话。
